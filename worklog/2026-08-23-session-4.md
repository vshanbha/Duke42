# Session 4 — 2026-08-23

## What Was Done

### 1. E2E Test Failure Fix
- Diagnosed `E2ETest` failure: "Server process died during startup"
- Root cause: fresh builds package the jar with `vaadin.productionMode=false`
  (set in session 3 for `mvn spring-boot:run` dev mode), but the fat jar
  excludes the optional `vaadin-dev` dependency, so Vaadin fail-fasts with
  `'vaadin-dev-server' not found` and Tomcat never starts
- Old jars (built before the yaml change) still had production mode baked in,
  which masked the problem until the next `mvn clean package`

### 2. Test Hardening
- `E2ETest` now launches the jar with `--vaadin.productionMode=true`
  (fat jars can never use Vaadin dev mode)
- Replaced `pb.inheritIO()` (which corrupted surefire's native stream and
  hid the real error) with redirect to `target/e2e-server.log`
- On startup failure, the test now prints a tail of the server log so the
  root cause is visible in test output

### 3. E2E Moved to Failsafe (`verify` Phase)
- Renamed `E2ETest` → `E2EIT` (Maven convention; surefire ignores `*IT`,
  failsafe picks it up)
- Added `maven-failsafe-plugin` to backend pom bound to
  `integration-test` + `verify`, so E2E runs after packaging instead of
  failing with "Jar not found" during `mvn clean package`
- Simplified CI: backend steps collapsed into a single `mvn clean verify`
- Updated AGENTS.md (commands, test counts, pitfalls), backend README
