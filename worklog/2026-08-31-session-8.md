## Lessons Learned

1. **Sandbox wrappers are necessary** — `GlobTool`/`GrepTool` from `spring-ai-agent-utils` accept arbitrary `path` arguments. Without wrappers, an LLM can glob/grep outside the project directory. `FileSystemTools` has built-in `allowedDirectory` enforcement, but Glob/Grep do not.

2. **`toRealPath()` is needed for symlink safety** — `toAbsolutePath().normalize()` doesn't resolve symlinks. A symlink inside `allowedDirectory` pointing outside would pass the `startsWith` check. Use `toRealPath()` when the path exists, fall back to `normalize()` for non-existent paths.

3. **`ToolCallbacks.from()` works with POJO `@Tool` methods** — The sandbox wrappers are plain POJOs with `@Tool`-annotated methods, same as the original tools. Spring AI's `ToolCallbacks.from()` scans for `@Tool` annotations and wraps them into `ToolCallback[]`.

4. **Package-private classes cause cross-package test issues** — `UserVisibleToolCallback` is package-private in `com.example.cliai.agent`, so tests in `com.example.cliai.agent.tools` can't access it. Moved relevant test to correct package or used raw `ToolCallback` interface.

5. **`commit-message-lint.sh` checks every commit** — Not just the tip. All commits in `main..HEAD` must pass. Squashing to a single commit is the simplest fix when older commits have lint issues.

6. **Update the same PR for reviewer findings** — When reviewer agent flags issues, add fixup commits to the same branch and force-push. Do NOT create a new PR. Rule already in AGENTS.md line 196.

7. **Worklog commits should be separate** — Don't bundle worklog entries with feature commits. Keep PRs focused on one concern.

8. **Test count drift is a recurring trap** — Every time tests are added or removed, all doc counts must be updated in lockstep. The reviewer caught this 3 times across review rounds. Consider a CI check or single source of truth for test counts.
